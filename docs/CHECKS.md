状態：**下書き（2026-09-25）**。アプリ・フロー・テスト環境は未構築。コマンドは未設定、検証は未実施。仕様と規律は`docs/REQUIREMENTS.md`、画面仕様は`docs/ui/`、実施結果は`docs/TASKS.md`を正式な記録先とする。

## 検証の方針

- この文書を正式な検証方法の記録先とする。自動テスト、型チェック、Lint、ビルド、実行場所、前提条件、対象環境、成功の判定方法を記載する。
- 未構築時は未設定とする。構築後に実在する設定と成功・失敗の動作を確認して更新する。存在しないコマンドを推測して案内しない。
- 変更に応じて必要なテスト、型チェック・Lint・ビルドを選び、実行方法と対象を記録する。必須の確認は実施し、該当しない確認は理由を残す。合格後に同じ確認を理由なく繰り返さない。
- モックのUI調整中は、変更した画面と影響する既存画面の表示・文言・主要操作を短い間隔で確認する。毎回すべての機能テストを走らせる前提にはしない。本処理や保存を結合した後は該当する機能・データ・回帰テストを実施し、公開候補では工程11の全体確認を行う。テストを省いたことを合格と記録しない。
- 文書のみの変更では内容、参照、差分を確認する。コード用テストの成功を文書の網羅性の証拠にしない。
- 実施できない検証は理由・未確認範囲・影響・担当・次の行動を報告する。自動テスト合格と実機合格を混同しない。
- 新規の失敗と既存の失敗を区別し、実行環境・対象版・再現条件を記録する。

## TDDの適用と代替確認

TDDは期待結果のテストを先に作り、想定した失敗を実行で確かめてから処理を実装し、成功と回帰を確認する進め方。下表は**予定**であり、テスト資産・コマンド・結果は未設定／未実施。採用方式で自動実行できない場合は理由と代替方法を実装前に記録して判断を受ける。

| 対象 | TDDと理由 | 代替・追加確認 |
| --- | --- | --- |
| T-008：件別入力の妥当性、保存失敗時の転記停止、開始前取消 | 適用。入力・保存・取消の条件を機械で判定できるため。 | 実際のファイル選択・保存結果はブラウザと保存先で確認。 |
| T-009：日付照合、件別停止、状態遷移、重複判定・再実行許可 | 適用。異常値・結果不明の条件分岐に回帰リスクがあるため。 | フロー接続とExcel反映は架空データで実機確認。 |
| T-010：転記照合と人の判断の別保存、レビュー入力条件・結果保存 | 適用。保存の分離と理由必須を機械で判定できるため。 | 役割表示、4画面の遷移、再表示後の記録を実機確認。 |
| T-001～T-003：方式の探索的検証 | 適用しない。実環境で方式の可否を調べる作業だから。 | 架空データで実操作し、版・結果・証拠・制約を記録。 |
| T-004～T-007：設計・文書・データ準備 | 文書設計と準備自体には適用しない。 | 要件・画面仕様・規律の照合、参照・差分、架空データ確認、独立レビュー。 |
| UIモックの余白・文字・配置 | 適用しない。見た目の調整だから。 | 対象と影響画面の文言・欠け・重なり・主要仮操作をブラウザで確認。 |
| クラウド接続・Excel実反映、T-011・T-012 | 単体ロジックのTDDだけでは合格にしない。 | C01～C09の実機再現とExcel実内容、C07の相手の操作・受入を確認。 |
