# 確認方法

## 検証の方針

- この文書を正式な検証方法の記録先とする。実施した確認と未実施を分け、未確認を合格と記録しない。
- C08の最小確認は完了済み。対象は修正のStudio保存と、架空ログ1件の保存結果・Dataverse行／添付の読戻し。処理開始は押していない。
- 既に合格した正常複数件の転記、Excel本文照合、レビュー往復は既存証拠を参照し、繰り返さない。
- 保存・開始・Excel書込の結果が不明なら「要確認／未確認」のまま止める。今回の版では再保存・再実行・取消後の再開を確認・提供しない。
- 今回は一般公開、課金、実務データを使わない。公開確認は対象外。

## C08の1件確認結果

2026-09-26、C08候補をChromeのPower Apps Studioで保存し、Canvas MCPで6 YAMLを再同期した。候補と正規化後のテキストは一致し、Screen1の差は改行のみだった。公開はしていない。

1. 実行前にCLIでA/A/8371/2026-09-26の既存件0件を確認した。
2. プレビューで[samples/t006/save-check-20260926-run8371.txt](../samples/t006/save-check-20260926-run8371.txt)を1件添付し、環境A、サーバーA、実行回8371、対象処理日2026-09-26で保存した。
3. 画面は「保存済み」と表示し、進捗一覧は「転記処理: 未処理／Excel実反映: 未確認」だった。処理開始は押していない。
4. CLIでDataverseの件1行、関連添付1件、4項目と保存状態を読み戻した。添付名は一致し、205バイトでローカルとサイズが一致した。

この結果は、今回の短い正常保存1件の合格である。保存失敗・応答不明・部分添付時の全分岐、同一件ID再保存、再起動後の状態復元、Excel転記は確認していない。これらをC08全体の合格と解釈しない。

コマンドは実在する設定と実行結果を確認してからTASKSへ記録する。CLIの認証プロファイル名や秘密値をREADMEへ記載しない。詳細な実行時刻・対象版・読戻し証拠は`docs/TASKS.md`のT-011へ記録する。

## TDDの適用範囲と代替確認

| 作業 | TDD | 方法と現状 |

| フロー更新候補の事前照合 | 適用する。差分範囲と版の違いを誤ると実フローへ影響する | `test_prepare_workflow_patch.py`は4件合格とTASKSに記録済み。今回再実行はしていない。実フローの状態・読戻しはDeveloper環境で別途実施した記録をTASKSで確認 |
| Canvas Studioの表示、添付操作、接続設定、保存先読戻し、Excel実反映、既存正常／レビュー経路 | TDDを適用しない。Studio・接続先・実サービスの動作はローカル単体テストでは確認できない。成功済み経路は繰り返さない | 代替としてCanvas MCPの6 YAML検査、Studio保存後のMCP再同期、今回のC08架空1件の画面表示とDataverse読戻し、既存D/G転記・Cレビューの記録を使う。確認範囲と未実施分岐は上の表とTASKSに記録 |
| 文書とREADMEの操作説明 | TDDを適用しない。仕様・参照・説明の確認はコードテストで判定できない | 差分、相互参照、URL、記載したサンプルの実在と入力値を確認する。今回コードテスト・型チェック・Lint・ビルドは未実施 |

すべてのPythonコマンドはローカルファイルを対象にし、Power Platformへ接続しない。実機の対象環境はDeveloper環境の非公開アプリ。Chrome/StudioやCLIでの外部サービス確認はローカルTDDと別の証拠として扱う。C08の短い正常保存確認は完了しているが、障害を意図的に起こす試験や失敗経路全体の受入には置き換えない。

## 文書変更の確認

文書だけを変更した場合は、対象要件との整合、リンク先の存在、記載したファイル名・URL、差分を確認する。コード用テストは文書の網羅性を証明しない。文書変更時に実行するコードテスト・型チェック・Lint・ビルドは該当なし。
