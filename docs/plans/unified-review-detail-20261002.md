# ログ・結果・レビューの確認を同じ画面に統合

具体案を示した後の「そこを修正しておいてください」を実行承認と扱う。独立レビューと大規模試験は利用者の継続指定により行わない。

## 対象と完成形

- Screen2の「レビューを確認」を除き、「ログと結果を見る」から対象GUIDを保持してScreen3へ入る。
- Screen3で元Excel・元ログ・照合結果・差異IDと担当者の判断・コメントを見て、レビューする。未依頼／差し戻しは担当者の編集・依頼経路を保持。依頼中／再依頼／完了は担当者入力を通常色の読取専用表示にする。
- 依頼中／再依頼に限り、既存の実演用担当者役・レビュアー役の切替と「レビュー結果：承認／差し戻し」を表示。別人のアクセス権制御を新設したものと扱わない。差し戻しは理由必須。レビュー状態の保存値は承認→確認済み、差し戻し→差し戻しで既存Teams通知と保管条件を維持する。
- 保存直前に同一GUID・バージョン・依頼状態を読み直す。保存後は同一件のレビュー状態と差し戻し理由を読み戻して一致した場合だけ保存済みの表示へ置き換える。完了後もScreen3にとどまり承認／差し戻しと理由を表示する。失敗・結果不明は理由を表示して連打・無条件再送を止める。
- 戻るは矢印なし左上の「進捗一覧に戻る」。戻る際に既存と同様担当者役へ戻す。ページ切替・全体スクロール・未依頼文非表示を維持。
- Screen4は既存参照の互換用に残し、「ログと結果を見る」でScreen3へ移動する操作だけにする。通常操作からは入らない。新画面・データソース・表・列・フロー・照合／Excelロジックの変更なし。検査でOnVisibleのNavigateが拒否されたため、互換経路は明示ボタンとする。

## 操作契約

| 操作 | 条件・対象 | 更新と証拠 |
|---|---|---|
| 結果を見る | 一覧の選択件GUID | 記録更新なし。同一の元2ファイルとID差異・担当者判断・レビュー結果を表示 |
| 役割切替 | 依頼中／再依頼かつ子ファイル2件・処理完了・結果読戻し一致 | 既存varDemoRoleの実演切替のみ。役割ラベルと入力可否に反映 |
| 承認 | レビュアー役・上記条件・版不変 | 同一件のレビュー状態=確認済み、理由空。読戻した承認結果を同画面表示 |
| 差し戻し | レビュアー役・上記条件・版不変・理由必須 | 同一件のレビュー状態=差し戻し、理由。両値の読戻し後に同画面表示 |
| 担当者再依頼 | 差し戻し・担当者役 | 既存の確認ダイアログと保存／読戻し条件を保持。レビュー結果・理由は参照可能 |
| 一覧へ戻る | 保存／確認中以外 | 通知・データ更新なし、担当者役に戻しScreen2へ |

## 実施順序と最小確認

1. 最新6定義を別フォルダーへ同期して保全。既存ローカル変更を上書きせず候補を作成。
2. Screen2／3／4だけを変更。既存元ファイル・照合表示・依頼処理を保持し、旧レビュー保存の同一件／版／依頼状態の制限を引き継ぐ。
3. 最小ローカル確認で一本の入口、両判断・保存値・理由必須・対象版確認・読戻し・再送抑止・スクロール下端・他画面不変を確認。
4. 既存承認済みのMicrosoft Power Apps編集サービスへのcompile_canvas送信・Studio保存と保存後6定義読戻し。一般公開は行わない。
5. 既存件の読取と画面遷移・選択／キャンセルだけを確認。新規件・添付・結果Excel・レビュー確定・Teams通知は増やさない。依頼中の件がなければその条件の実表示は未確認と明示し、利用者確認手順に含める。
6. 保存済み定義をcanvas/currentへ反映し、要件・画面仕様・CHECKS・TASKSを更新。URLと既存件からの操作手順を報告。

## 外部操作と復旧

外部送信は既存アプリの画面定義のみ。Dataverseの実テスト書込み・Teams送信・SharePointファイル操作・公開・購入・削除は含めない。UIのレビュー確定時は従来と同じ状態／理由の更新により既存通知が作動する。AIは今回確定しない。費用・新規権限を要求されたら停止。復旧は今回の3画面変更だけを保全定義から戻し、既存データを消さない。構文合格を実保存・通知成功と報告しない。
