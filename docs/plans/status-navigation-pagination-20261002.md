# 状態文言・戻る操作・ページ切替の修正

ユーザーはチャットで具体案を承認し「そんな感じで修正して」と実行依頼した。対象はDeveloper環境の非公開アプリの進捗一覧とログと結果の確認。サブエージェントと大規模試験は使わない。

## 対象と完成条件

- Screen2.pa.yaml：保存された転記照合を「担当者の確認結果」、処理結果判断を「処理結果の判定」として表示。空欄はそれぞれ「未記録」「未判定」。レビュー状態の空欄／未依頼は「未依頼」。照合完了前に保存された確認結果を表示しない既存条件は保持する。
- Screen3.pa.yaml：入力欄も「担当者の確認結果」「処理結果の判定」に統一し、レビュー空欄は未依頼。戻る操作は「← 進捗一覧に戻る」として左上、タイトルより上へ置く。既存の遷移先、依頼確認中の無効条件を保持する。
- 不足IDと予定外IDのページ切替を、それぞれ一覧直下の中央に一組で配置。「前の10件」「1～10件／全50件」「次の10件」。各10件、全件数、初回と最終ページの無効条件、画面を開いたときのリセットを保持する。
- タイトル／識別情報／左列の結果を、戻る操作と重ならない位置へ追従させる。全体スクロール、右列、依頼ダイアログは保持。
- App、受付、レビュー画面、保存値、Patch・SubmitForm・OnSelect・フロー・表・Excel様式は変更しない。新規照合、依頼確定、通知、削除、公開は実行しない。

## 順序と変更先

1. 現在のStudio定義6ファイルを outputs/canvas-20261002-navigation-before に同期して退避。既存ローカル変更と照合する。
2. 同期コピーを候補フォルダーへ複製し、上記2画面の対象プロパティだけ編集。_EditorStateは編集しない。
3. 既存承認を引き継ぎ、Microsoft Power Apps編集サービスへ候補を送信してcompile_canvas。非公開Studioで保存し、全6定義を再同期。
4. 戻り先と保存処理の式が不変であることを差分確認。既存の50件差異の結果でページ切替、戻る位置、進捗の未記録表示を確認する。照合やレビュー依頼は行わない。
5. 保存後のScreen2／Screen3をcanvas/currentへ反映し、画面仕様・確認結果・作業状態へ記録。

## 確認・復旧・承認範囲

画面の文字・配置の限定変更のため、TDDや全面回帰は行わず、構文検査・保存後読戻し・変更箇所の実表示で確認する。保存前定義を保持し、問題時は今回変更したプロパティのみ戻す。既存データを消して回復しない。通常契約内の画面定義編集で、課金操作は含まない。実機は既存テスト結果の閲覧とページ切替だけ。外部送信先と内容は既存compile_canvas送信・非公開保存の承認範囲内。ユーザー受入・公開とは区別する。
