# 進捗一覧とログ・結果確認の表示改善（2026-09-30）

## 目的と承認範囲

ユーザーが2026-09-30に確認した方向に従い、既存の進捗一覧（Screen2）とログと結果の確認（Screen3）を、照合の状態・差異・人の確認が順に読める表示へ直す。4画面構成、Dataverse列、フロー、結果Excelの計算、担当者の保存・レビュー依頼条件は変えない。前回の変更を残し、非公開Developerアプリに保存する。公開、新規件の作成、既存件の更新・再処理はしない。

## 表示と判定

| 項目 | 変更後 | 根拠・例外 |
| --- | --- | --- |
| 進捗の左端 | 操作不能の丸と状態名。灰「開始前」、黄「照合中」、緑「照合完了」、赤「差異あり／要対応」。色だけに意味を持たせない | 停止・結果不明・失敗理由・結果Excel読戻し不一致とMQ差異は赤。開始受付済み／処理中は黄。Excel読戻しとMQ一致が確認できた完了は緑。保存済み等は灰。差異は処理失敗と断定しない。 |
| 進捗の説明 | 「ファイル: 保存済み」「照合: 未開始／進行中／完了／停止／結果を確認できません」を使用し、「転記処理」「Excel実反映」は通常表示から外す | 結果Excelの実際の確認結果は緑の条件に使い、問題がある場合は赤と理由で知らせる。 |
| 人の確認 | 「担当者の確認: 未記録／記録値」「処理結果の判断: 未記録／記録値」「レビュー: 依頼前／現行状態」 | 照合が未完了なら担当者欄は「照合後に確認」。データ上の値は変更しない。 |
| 識別 | 進捗一覧と詳細の主領域では件GUIDを出さず、ログ名・対象日・環境／サーバー・受付日時を表示 | 同名再照合は受付日時で区別する。技術的なGUIDは詳細で補助的に参照可能にする。 |
| 進捗一覧の幅 | 大きなPC画面ではカード幅を広げ、本文と操作をまとまりとして使用する | 文字を1行に詰めず、狭い画面では縦に読む。 |

## 変更対象と順序

1. Canvas Authoringから現在の6定義を同期し、`Screen2.pa.yaml`の状態丸、文言、件幅・余白を変更する。
2. `Screen3.pa.yaml`の識別、結果要約、差異の見出しとID行、ファイルとレビューの配置を変更する。GUIDは補助情報として保持する。
3. Canvas構文検査、非公開Studioで保存、6定義の読戻しを行う。PC幅で差異あり／なしの既存件を読み取り専用で表示し、赤・黄・灰の条件は式と既存状態で確認する。新規の試験件は作らない。
4. `docs/REQUIREMENTS.md`、各画面仕様、`docs/CHECKS.md`、`docs/TASKS.md`、`docs/HANDOFF.md`へ現行表示と未確認事項を記録する。

## 合格条件と限界

- 進捗の各件に色付き丸と状態名があり、差異ありは赤「差異あり」、差異なしで照合済みは緑「照合完了」、理由付き停止は赤「要対応」になる。
- 件GUIDと「—」を主要表示に使わず、ログ名・受付日時で件を見分けられる。
- 詳細画面では照合結果の直下に差異の種類とIDがあり、レビュー状態は差異欄に混ざらない。
- 保存済みの非公開Studio定義を読戻せる。既存の結果Excel、処理フロー、件・添付は書き換えない。
- 狭い画面でのページ全体スクロールは過去に未達であり、この変更では新しいスクロール容器を導入しない。見える範囲に不足が残れば未確認として報告する。

## 外部操作と戻し方

Canvas構文検査で編集サービスへ画面定義を送信し、Studio保存で非公開の編集版を更新する。既存契約内で費用増加は想定しない。公開しない。失敗時は同期済みの直前6定義を保存しているため候補を戻して再検査する。データ変更はない。
