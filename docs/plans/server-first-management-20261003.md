# サーバーを親、環境を子とする管理画面への修正

## 承認と現在位置

ユーザーが「1台のサーバーの中に複数の環境がある」と明示し、「そうですそれです。修正してほしいです。それに伴いUIも変わると思います」と実行を依頼した。親子関係の修正は承認済み。本書は実装前の詳細計画。以前の環境を親にする計画を、この変更範囲について置き換える。

まずHTML見本をサーバー中心へ修正し、UIと保存範囲を確認できる形にする。クラウドの既存同期プラグインの意味変更と新たな実データ試験は、以前の「新規追加・架空2行・照合4件」の許可と異なるため、具体的な範囲をまとめて確認してから反映する。サブエージェントは使わない。

## 調査結果

現行登録はDataverseの架空ログ転記先1行に環境名・サーバー名・両方の使用状態を保存する。管理保存処理は環境名で全行をまとめ、環境名称変更／終了をまとめて適用していた。画面だけ逆にすると、保存対象も逆転したように見えながら実際の更新範囲が一致しない。

2026-10-03の読み取りでは登録12行、サーバー名12種類。環境Aには2種類のサーバー、以前の動作確認環境にも2種類のサーバーがある。すべてサーバー使用中、環境使用中または未設定（使用中扱い）。現在は同じサーバー内の使用状態矛盾がなく、そのままサーバー別に整理できる。追加されていた登録も削除・改名・別サーバーへ移動しない。反映直前に再読込して再確認する。

## 完成形とUI

- 入口と画面名は「環境・サーバーの管理」、戻るは左上の矢印なし「進捗一覧に戻る」を維持。
- PCは左にサーバー一覧、右に選んだサーバーの環境一覧。全体最大1,200px中央。760px以下は上にサーバー、下に環境。
- 左見出しは「サーバー」、上部に「サーバーを追加」、使用中／使用終了の切替。登録枠の中に名前、「環境を見る」、「名称を変更」、「使用を終了／再び使用する」を置く。
- 右見出しは「{サーバー名}の環境」。独立した「対象の環境」行はなくす。上部に「環境を追加」、使用中／使用終了の切替。各環境枠に名前と名称変更／終了／再使用。
- 環境を見るで所属一覧を切り替え、右側（狭い画面では下側）の見出しへ焦点・表示位置を移す。名前のクリック選択、選択中文字、選択した枠の青い強調、下部成功結果は追加しない。
- 登録枠内の操作を維持し、登録が増えても一覧の末尾へ共通変更ボタンを置かない。長い名称は折り返す。横並びでは操作ボタンが枠内に収まる。

## 操作と保存対象

| 操作 | 入力・対象 | 保存する範囲 |
|---|---|---|
| サーバーを追加 | サーバー名＋対象の環境名 | 新しい組み合わせ1行。共通保存先の確認後に確定 |
| 環境を追加 | 選んだサーバー＋環境名 | 同じサーバー内へ1行追加。使用終了したサーバーへの追加は禁止 |
| サーバー名の変更 | 左のそのサーバー | そのサーバー内の全行のサーバー名を一括変更 |
| 環境名の変更 | 右のその環境 | そのサーバー内の対象環境1行だけ変更 |
| サーバーの使用終了／再使用 | 左のそのサーバー | 全所属行のサーバー状態だけを一括変更。個別の環境状態は保持 |
| 環境の使用終了／再使用 | 右のその環境 | 対象1行の環境状態だけ変更。終了したサーバーでの環境再使用は禁止 |

サーバー名重複は全サーバー（使用終了を含む）で拒否。環境名重複は同じサーバー内（使用終了を含む）で拒否。異なるサーバーには同じ環境名を登録でき、それぞれを別の組み合わせとして管理する。名前の空欄・100文字超過・同時変更・保存先確認失敗を拒否する。

## 文言

- サーバー追加の入力：サーバー名、対象の環境名。環境追加では対象の環境名だけを入力し、見出し「{サーバー名}に環境を追加」で対象を示す。2026-10-03のユーザー注釈により、環境名の入力ラベルは追加・名称変更とも「対象の環境名」に統一する。
- 名称変更の見出し：「サーバー名を『旧名』から『新名』に変更しますか？」または環境名。実表示の括弧は「」。本文のログ名称確認は既存を維持。サーバー変更には「このサーバー内のすべての環境に適用されます。」を明示する。
- サーバー終了：「{サーバー名}を使用終了にしますか？ このサーバー内のすべての環境が使用できなくなります。」
- 環境終了：「{環境名}を使用終了にしますか？ このサーバーでは、この環境が使用できなくなります。」
- 使用終了したサーバーでの環境追加／再使用拒否：「このサーバーは使用終了です。サーバーを再び使用してから操作してください。」
- 保存中・未知の結果は連打と再送を止め、読み直す。操作後は保存値を読み直して一覧へ反映する。説明用の常設注釈や成功通知は追加しない。

## 技術上の変更

1. 非公開アプリ7定義、既存管理フロー、Custom API／同期プラグイン、登録12行を読み戻して保全する。途中のユーザー編集を上書きしない。
2. HTML見本の表示・入力・確認を先に修正する。仮データのみ使用し、クラウド保存処理は呼ばない。
3. 同じ表と同じ列を使う。cr6cb_isactiveはサーバー全体の状態、cr6cb_environmentenabledはサーバー内の個別環境状態。列追加、履歴変更、既存登録の移行・削除は不要。
4. 管理保存のグループ判定をサーバー名へ変更し、サーバー全体の処理を同期トランザクション内で一括保存する。途中の失敗は例外を伝えて全体取消し。古い版や所属行の増減は拒否し、重複も保存直前に再確認する。
5. 書込み要求へ管理方式の版 server-first-v1 を追加する。旧画面から届く書込みは「管理画面が更新されています。画面を開き直してから操作してください。」で拒否する。listの読み取りは従来互換。
6. 管理フローは既存のJSON受け渡し・共通保存先確認を利用する。新しい拒否理由が一般的な失敗文に置き換わらないよう、エラー応答の文言選択だけ更新する。接続先・権限は増やさない。
7. Screen5のサーバー別一覧、個別環境一覧、追加／編集／終了の操作と版証明を接続する。現在の標準全体スクロールと焦点移動を再利用する。生成処理も新方式へ揃える。
8. 受付は既存の「両方が使用中の組み合わせのみ」という条件を維持する。現在の環境からサーバーを選ぶ受付順序と、ファイル2件・照合開始操作は今回変更しない。管理画面の親子と、照合入力の選択順序は区別する。
9. ログの環境・サーバー一致、MQ ID比較、結果Excel、SharePoint保管、レビューとTeams通知は変更しない。既存照合フローは更新しない。
