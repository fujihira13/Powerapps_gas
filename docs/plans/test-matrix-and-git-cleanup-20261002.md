# 環境A・Bの確認用ファイル作成とGit整理

## 承認・目的
ユーザーの2026-10-02の依頼により、確認済みの6組・12ファイルを作成し、溜まった変更を分類してコミット・通常のpushまで行う。アプリ・フロー・クラウドデータへの変更や実機照合は含めない。以前に承認・実施した旧入力の削除はGitへ記録する。新しい削除や履歴の書き換えはしない。

## 入力仕様と手順
1. Dataverseの転記先を読み、環境AはサーバーA、環境BはサーバーBが有効であることを確認する。ログ本文には現在の保存値（架空環境A/B、架空サーバーA/B）を用いる。画面表示は環境A/B、サーバーA/B。
2. samples/mq-acceptance/environment-a と environment-b に、それぞれ差異0、1、50のxlsx/txtを作る。Excelは現行契約のBatch_Inputシートのみ、A1タイトル、A2 MQ_ID、A3:A102に100 ID。環境AはMQ-3001～MQ-3100、環境BはMQ-4001～MQ-4100。ログは100、99、50 ID。1件の不足は末尾ID、50件は後半50 ID。日付・実行回は入れない。
3. Artifact Toolで作成・再計算・表示確認・保存する。保存したExcelからIDを読み、ログとの集合差分が0/1/50、余分なIDと重複が0であることを確認する。READMEに絶対パス、選ぶ環境・サーバー、期待IDを記載する。
4. Gitの未追跡・変更・削除を分類する。最新の保存済みCanvas定義をcanvas/currentにまとめ、元のコピーはローカルに保持する。今回変えない他の画面は最後の確認済み版を使い、来歴と限界を明記する。
5. 途中の画面スナップショット、クラウドの定義バックアップ、実データ、添付本文、画像プレビュー、生成ラッパー、診断出力を.gitignoreで除外する。実装・最小検査・検査用見本・資料・今回の12入力をコミットする。既追跡の過去資料は無断で削除しない。
6. 最新READMEから削除済み結果への案内や旧日付必須の説明を除き、新しい確認方法へ更新する。分類表とGit検査結果をdocsへ記録する。
7. ステージした差分・ファイル一覧と認証情報らしい値を検査する。重複の画面定義とバックアップが入らないことを確認する。既存リモートorigin（github.com/fujihira13/Powerapps_gas.git）の現在のmainへ通常のコミット・push。強制pushなし。push失敗や競合があれば既存履歴を上書きせず報告する。

## 完成条件・制限
6組をローカルで確認でき、差異IDの期待値と操作手順が分かる。Gitには保守するファイルと必要な再現材料が残る。クラウド照合・通知はユーザーが実行する。公開・課金・権限変更はない。新規バックアップ等は削除せず対象外として残す。コード検査は必要箇所だけとし、サブエージェントや大規模試験は使わない。
