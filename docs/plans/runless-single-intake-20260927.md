# 1件受付・実行回なし化の実装計画

## 承認と適用範囲

2026-09-27、ユーザーは本計画の実装を「PLEASE IMPLEMENT THIS PLAN」で依頼した。旧承認・実機の履歴はそのまま保持し、本計画の仕様を受付・識別・照合・出力に適用する。これは実装依頼であり、公開承認ではない。Dataverseキー変更、クラウド定義の保存、実API試験は`docs/WORKFLOW.md`に従い、各操作の対象・変更内容・架空データ件数を示して個別確認を得る。

## 動作

- 受付は1件ずつ行う。`.txt`ログ1つを必須、MQ照合を使う場合は`.xlsx`バッチ入力ブック1冊を追加する。4画面、ログだけの経路、担当者確認とレビューを維持する。
- 対象処理日は当日を初期値にし、利用者が変更できる。実行回は入力させない。
- 保存は対象1件と添付をフォームのサポート対象Attachmentsコントロールから記録する。保存後にDataverseの件と関連添付を読み戻し、件ID・添付の数・名前・役割が受付内容と一致した場合だけ「保存済み」とする。保存と処理開始は別操作にする。
- 既存件のログ名またはバッチブック名と一致したときは、該当する過去件の受付日時（JST）と件IDを示して警告する。利用者が明示的に続行した場合は、新しい件として保存する。これはファイル名の注意喚起で、内容の同一判定ではない。
- 受付件表に任意の文字列列「バッチExcelファイル名」（SchemaName `cr6cb_Batchfilename`、最大255文字）を1つ追加し、新規MQ受付だけに元ブック名を記録する。新規件のログ名は既存ログ名を使う。列追加前の旧件は既存添付のファイル名メタデータを照会して比較し、新規件はログ名と新列のブック名を比較する。ログのみの新規件では新列を空欄にする。既存件の列値・添付は更新・バックフィルしない。
- 既存の件GUIDとDataverse `createdon`（JST表示）を各件の識別に使う。画面と新規結果Excelでは受付日時を`YYYY-MM-DD HH:mm:ss JST`、件GUIDを完全値で示す。保存中・処理開始中の同一件に対する連続操作を無効化し、開始済み件を再開始しない。同日・同じ環境・サーバー・対象処理日の別件は受け付ける。

## データ・照合・出力

- Dataverse件表で「環境・サーバー・実行回・日付」を一意にしている代替キーを特定し、依存関係を確認して廃止する。実行回列は任意項目として残す。新しい任意の「バッチExcelファイル名」列以外は、既存行・添付・結果Excelを変更・削除しない。別用途のキーは変更しない。
- 新しいログ見本は先頭3行を`処理日: YYYY-MM-DD`、`環境: ...`、`サーバー: ...`とし、実行回行を含めない。フローはこの3項目を対象件と照合する。4行目以降に従来形式の`実行回:`がある旧ログも受け付け、その値は必須条件にも照合条件にも使わない。
- 新しい結果Excelは`RunNumber`列を`ReceivedAtJst`列へ置き換え、件GUIDとともに書き込む。`ReceivedAtJst`は対象件のDataverse `createdon`を日本時間で表す。Excel出力後にこの2項目を読み戻し、保存値と一致することを確認する。過去に作られた結果Excelは変更しない。
- 進捗一覧・件確認・レビューは「受付日時」と「件ID」で対象を示し、従来の実行回を件識別に使わない。

## 確認条件

- ローカル：実行回行なしの新ログが処理日・環境・サーバー照合を通ること、いずれかの不一致がその件だけを止めること、旧ログの実行回行は任意で受け付けることを確認する。
- Canvas：受付1件、当日初期値と日付変更、対応するフォーム内添付欄、保存後読戻し、保存済み後の別操作による開始、同一件の保存中／開始中ボタン抑止を確認する。4画面の文言・欠け・重なりと受付日時・件IDの表示も確認する。
- Excel：新規出力で`ReceivedAtJst`と件GUIDを書き、両方を読戻し一致させる。既存結果Excelは読み取りのみで保全する。
- Developer環境の統合確認は架空データの新規件を最大2件とする。`samples/mq-id/mq-id-5-items-runless.txt`と`mq-id-5-items-20260927.xlsx`を2件で使い、同じ日・環境・サーバー・対象処理日で保存できること、同名ファイル警告に1件目の識別情報があること、明示続行で2件目を新規保存できることを確認する。うち1件だけ開始して結果を確認する。既存件・既存runは再開始しない。

## 実施順と保護

1. アプリ、フロー、Dataverseキーと列、Excelテンプレートの現在定義を保存・記録する。
2. ローカルのログ検査・Canvas・出力処理と各確認を実装する。
3. Dataverseの代替キー廃止、実行回列の任意化、任意文字列列`cr6cb_Batchfilename`（表示名「バッチExcelファイル名」、最大255文字）の追加は、実際の定義・依存・既存データへの影響を読み取り、操作範囲を説明して個別確認後に行う。列の作成後も過去件の値は埋め戻さない。
4. Developer環境へ定義を保存する前と、最大2件の実機確認前に、対象定義／架空入力／予想される新規レコード・Excel数を説明し個別確認する。保存後は定義を読み戻して差分を照合する。
5. 不具合時は既存データを削除しない。旧キーへ単純に戻せない場合は重複データを維持したまま修正し、停止・影響を記録する。

実装、クラウド変更、統合試験の各状態は`docs/TASKS.md`と`docs/CHECKS.md`に事実に基づき記録し、未実施を合格としない。
