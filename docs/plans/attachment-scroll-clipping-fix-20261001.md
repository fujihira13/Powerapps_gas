# 添付欄と確認画面の見切れ修正

## 対象と承認

2026-10-01にユーザーが提示した未添付欄の文字切れ、確認画面下部のスクロール不能を修正する。既承認の非公開Canvasアプリの画面定義送信・検査・Studio保存・表示確認の範囲で進める。今回はフロー・データ・公開を変更しない。

## 実装手順

1. 最新定義6ファイルを clipping-prechange に保存済み。別の clipping-stage へコピーし、Screen1とScreen3だけ変更する。
2. 受付の標準添付欄は、未添付時だけ高さを増やし、添付操作が欠けないようにする。添付後のファイル名・変更・削除、1ファイル制限と保存ロジックは維持する。
3. 確認画面の通常の内容を縦スクロール領域に置く。内容の高さは最下部の説明・ID欄から算出し、表示可能な高さを超える場合に画面をスクロールできるようにする。依頼の確認ダイアログは画面内に固定する。以前の親変更で表示不良が起きたため、この画面のコントロール名は新しくして参照式も合わせる。
4. 構文検査後にブラウザーで、未添付2欄、添付後の表示、低い画面での確認画面の下部へのスクロールを確認する。照合開始・依頼確定・通知送信は行わない。
5. 非公開アプリを保存し、定義を再同期して変更箇所を読み戻す。確認結果と制限を引き継ぎ資料へ記録する。

## 完了条件

- 未添付の「Excelを添付」「ログを添付」が全部見える。
- 確認画面の右側最下部までホイールで移動できる。
- App・進捗一覧・レビュー・保存や依頼の処理内容を変更しない。
- サブエージェント・大規模試験は使用しない。

## 実装時に発見した追加の表示不良

依頼確認の背景と文字の重なり順が崩れた。確認用コンテナー案も作ったが、別の編集セッションの定義と実画面が一致しなかったため、最終実装には使わない。Studio上で質問文・対象ログ名・キャンセルを白い背景より前面へ移動し、表示とキャンセルを確認した。依頼する／キャンセルの実行式は従来通り。

## 完了確認

未添付の2欄、添付後のファイル名・変更・削除、1920幅と1366×650での確認画面の最下部へのホイール移動を確認済み。Studio保存済み・非公開。確認ダイアログとキャンセルも確認済み。実画面のScreen3はStudioの「コードを表示」から全量取得し、`outputs/canvas-20261001-clipping-verified-save/`に保全した。別セッションのMCP同期は最終Studioの定義と違ったため、最終Screen3の根拠にしない。通常内容の縦スクロールと画面直下の確認ダイアログが最終構造。候補stageも検証済み保存定義に合わせた。
