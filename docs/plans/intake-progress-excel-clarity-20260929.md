# 受付・進捗・照合結果Excelの表示修正案（承認待ち）

## 現状と目的

更新対象一覧のExcelにある予定MQ IDとサーバーログに記録されたMQ IDを比較する、という既承認の目的を維持する。現行の結果Excelは1シートに予定6件・ログ記録5件・差異1件を出しているが、内部用語と2列だけの明細で比較元が分かりにくい。画面の「要確認」は差異ありと処理不能を混同し、受付の不足文言と添付の広すぎる欄、保管操作の文言も直感的でない。

## 提案する表示

1. 進捗一覧：新規受付ボタンを「新しい照合を始める」にする。保管一覧は「完了した履歴を見る」、復帰は「進捗一覧に戻る」とし、一覧見出しも切替に合わせる。レビュー確認済みの行の操作は「完了履歴に移す」、履歴側では「進捗一覧へ戻す」とする。件・添付・結果の保存と削除条件は変えない。
2. 照合状態：受付だけの件は「照合前」、開始受付済み・処理中は「照合中」、結果の読戻し中は「結果を確認中」と示す。入力と結果の読戻しが完了し、差異0件なら「差異なし」、差異1件以上なら「差異あり」、処理が止まった／読戻せない場合は「照合できません」と理由を併記する。「要確認」を差異の有無の代表表示として使わない。ログにないIDを更新失敗と自動断定しない。
3. 受付：Excelだけ選ばれたら「サーバーログ（txt）を追加してください」、ログだけなら「更新対象一覧（Excel）を追加してください」と示す。両方ない状態では一般的な不足警告を出さない。標準の添付コントロールを維持し、PC画面の各欄に最大幅を設けて削除用×をファイル名から離しすぎない。2欄はPCで横並び、小さい幅では縦並びとする。
4. 新しく作る結果Excel：`MQ ID照合結果` 1シートを維持する。上部に「差異あり（1件）」または「差異なし（0件）」、更新対象一覧名、サーバーログ名、予定数、ログ記録数、ログ終端表示を日本語で示す。件IDは追跡用の小さな情報欄へ置く。明細を `MQ ID／更新対象一覧にある／サーバーログにある／結果` の4列にし、例は `MQ-0304／あり／なし／ログに記録なし` とする。差異行を強調する。`ALL SUCCESS` はログ終端であり更新成功の証明ではない、という注意は短く残す。元入力Excelと既存の結果Excelは変更しない。

## 変更・確認の範囲

CanvasのScreen1・Screen2の表示式と配置、結果Excelを書いて読み戻すOffice Script 2本、対応する要件・画面仕様・作業記録を変更する。Power AutomateのMQ抽出・比較ロジック、Dataverse表、レビュー条件、既存件・添付・結果Excel、公開設定は変更しない。Office Scriptの入出力契約は維持するため、フローの定義更新は想定しない。変更前の定義を保存し、Canvas構文検査とPCプレビュー、架空の差異なし／あり各1組によるローカルのExcel書込・読戻し確認を最小限実施する。非公開Studio保存とクラウドのOffice Script更新後は定義を読み戻す。新規件を作る実機試験は別途対象を限定して確認する。

## 承認境界

この案は未承認。クラウド送信先は既存Developer環境のPower Apps編集サービスと検証用Office Scriptで、実務データを送らず、新規件・購入・公開・削除を行わない。`docs/WORKFLOW.md`に従い、変更対象と送信範囲の承認後に反映する。
