# MQ ID照合の実装計画（2026-09-27承認済み）

## 目的と変更範囲

バッチ用Excelの予定MQ IDと実行後ログに記録されたMQ IDを件ごとに比較し、ログにないIDを示す。`ALL SUCCESS`はバッチの終了表示であり、全IDの反映成功とは表示しない。架空データで動くポートフォリオ機能を対象とする。

既存の非公開Power Appsアプリは4画面のままにする。既存のログのみの保存・転記と、担当者判断・レビューは残す。新画面、新しい件表、新しいフロー、実務データの取込み、公開は含めない。

## 入力と画面の動き

- 受付画面では、新規件に `.txt` ログ1つと、MQ照合を行う場合のみ `.xlsx` バッチ入力ブック1つを関連付ける。**初回の1件確認では、ファイル選択画面でログとブックを両方選び、「ログを選ぶ」を押す前に同じ件へ渡す。** 添付コントロールの `Items` コレクションはMicrosoftの仕様でサポート対象外とされているため、ログを確定した後からブックを追加する経路は未検証であり、案内・合格経路に含めない。複数件を同時受付する場合の組合せ確定方法も未確認。ブックを付けない従来のログ件も扱う。
- **初版の入力契約**は架空見本と同じ `Batch_Input` シート、A2=`MQ_ID`、A3以降にIDを1行1件、ログのID行は行頭の `MQ_BOX_ID=MQ-0001` 形式、終了行は `ALL SUCCESS` とする。2026-09-27に計画とともにユーザーが承認した。実務ファイル一般への対応は主張しない。
- 「保存」でファイルと4項目を件ごとに保存し、別の「処理開始」で既存フローを起動する。保存結果が不明なら従来どおり停止する。
- 進捗一覧には終了表示の有無・予定ID数・ログ記録ID数・欠落ID数を追加する。件ごとの確認画面には予定IDごとの記録有無・欠落IDを示し、元の2ファイルと結果Excelを参照できるようにする。レビュー画面の役割と操作は変えない。
- 結果Excelは既存の件別証跡Excelのコピーとし、従来のEvidence表を保ったままMQ照合の結果を別シートに追記する。元のバッチ入力ブックや関数入り業務ブックは変更しない。

## 処理規則

- IDは前後空白を除いて比較する。見本の `MQ-` と4桁数字に一致しない行、同じ入力内の重複ID、想定外のシート・列は入力エラーとして止める。ログにしかないIDも要確認として表示する。
- 添付は1件につきログ1つ、MQ照合件ではブック1つを追加した計2つとし、拡張子とファイル内容の両方で役割を識別する。必要な添付の欠落、同じ役割の重複、予想外の添付は処理前に停止し、結果Excelを作らない。受付の保存後は2添付と件IDを読み戻してから「保存済み」を表示する。
- `ALL SUCCESS`がなければログの完結を確認できないため、欠落IDを反映失敗と断定せず「ログ不完全・要確認」と表示する。終了表示があり欠落した場合も、人の判断前は「ログ未記録・要確認」とする。実サーバーの状態を直接証明する機能ではない。
- 従来の処理日・環境・サーバー・実行回の検査、結果不明時の停止、結果Excelの二重作成防止を維持する。
