# 日付に依存しないMQ照合とテストファイル整理

## 目的・承認範囲
2026-10-01のユーザー依頼：日付のないExcelとサーバーログを、取得当日・翌日・1週間後にも新しい照合として使えるようにする。差異なし／あり各1組を作り、不要なローカル見本を整理する。クラウド反映の具体的範囲は別途確認する。公開承認ではない。

## 変更
1. 受付の対象処理日カード、日付必須条件、日付の保存読戻し条件を外す。環境・サーバーと2ファイルの保存・読戻し、同一件の多重開始防止は維持する。4画面構成を維持し、日付カードの空白も詰める。
2. Dataverseの既存 `cr6cb_targetdate` を任意にする。列と旧件の値は残す。新規件には対象処理日を作って埋めず、標準の受付日時 `createdon` を使う。新列は追加しない。
3. 件別照合フローはログ本文とファイル名の日付を照合条件にしない。旧ログの処理日・実行回行はあっても無視する。環境とサーバーの照合は保持し、日付行の有無で行番号がずれても読み取れるようにする。MQ ID比較は変更しない。旧ログのみ分岐のExcel日付は空欄に対応させる。
4. 進捗・確認・レビューから対象処理日の表示を外し、既存の受付日時で区別する。SharePointの新規保管フォルダーは受付日のJST日付＋件GUIDにする。Teams通知は対象日を受付日時に替える。旧ファイル・旧フォルダー・既存件は更新しない。
5. `samples/mq-id/` に `mq-success.xlsx/.txt` と `mq-missing.xlsx/.txt` の2組を作る。両方ともExcel6 ID、成功ログ6 ID、差異ログ5 ID（欠落MQ-1004）。名前と本文に処理日を入れない。差異はバッチ失敗の断定ではなく、記録不足の検出を意味する。
6. 不要な旧見本の削除前に、実行コードの参照とファイル内容を確認し、対象一覧とSHA-256を残す。自動検査で使う旧見本は専用の検査用フォルダーへ移して参照を更新する。結果Excel、テンプレート、定義の前後スナップショット、クラウドの件・添付・証跡は削除しない。

## 対象・順序
最新Canvas6定義を同期済みの `outputs/canvas-20261001-date-independent-prechange/` から別の候補フォルダーへ複製する。Screen1～4を変更しApp/Hostは保全する。処理フロー生成元 `outputs/flow-implementation/build_flow_definition.py`、該当検査、SharePoint/Teamsフローの候補、現行要件・画面仕様・引継ぎを更新する。反映前のクラウド3フロー定義と列メタデータを保存する。列任意化→フロー3件→Canvas検査・Studio保存→定義読戻しの順。日付なしで新規件が作れる状態まで整えてユーザーの実機確認へ渡す。

## 最小確認
日付なし、古い日付行あり、環境不一致、サーバー不一致、空ファイル名・過長ログを局所検査する。Excel2冊のIDとログの差異を確認する。Canvas構文検査、変更4画面の表示、クラウド反映後の定義読戻しを行う。AIによる新規件作成・処理試験は今回行わず、ユーザーが2組を実機確認する。レビュー用サブエージェント・網羅テストは使わない。

## 費用・通信・復旧
既存Developer環境内のMicrosoft Power Apps編集サービス、Dataverse org3d6ad684.crm7.dynamics.com、Power Automateへ定義を送信する。列1項目と既存フロー3件、非公開アプリの保存だけを変更する。ユーザー試験で既存のSharePoint保管・Teams通知は通常どおり動く。追加費用・権限要求が出たら停止。反映失敗時は前後の定義から該当箇所を修正し、既存データを消さない。日付なしの新規件ができた後は必須列へ単純に戻せないので、受付を再び必須日付に戻す対応はしない。削除対象の未追跡見本は削除後Gitで復元できないため、再生成可能な入力だけを対象とする。
