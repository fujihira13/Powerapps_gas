# 担当者判断の一本化と戻る位置の統一

チャットの具体案への「他はその通りでいいと思います。対応お願いします」と、矢印不要の指示を承認として実施する。新たな製品判断を追加しない。対象は非公開Developerアプリの4画面。独立レビューと大規模試験はユーザー指定により行わない。

## 具体的変更

1. Screen1／Screen3／Screen4の進捗一覧へのボタンを「進捗一覧に戻る」、X=24／Y=18／高さ36に統一する。Screen3の矢印を外す。受付フォームとレビュー見出し・後続内容を重ならない位置に追従させる。レビュー画面の「ログと結果へ戻る」は別の遷移なので既存の右上に維持する。各OnSelectと連打／確認中の無効条件を保持する。
2. Screen3の一致／不一致の入力と見出しを除き、「担当者の判断：問題なし／要対応／判断保留」の一入力にする。自動差異判定と人の判断を区別し、差異0を自動的に問題なしへ選択しない。コメント、下書き保存、依頼確認→確定・キャンセル、再依頼、役割／元ファイル／処理完了／結果読戻しの制限を保持する。要対応・判断保留のコメント必須条件は、以前の異常・判断保留条件を引き継ぐ。
3. 既存の処理結果判断列へ判断を保存する。互換性のため問題なし→正常、要対応→異常、判断保留→判断保留と対応させ、画面では新文言へ戻す。転記照合列へ新しい操作から書き込まず、既存値を変更・削除しない。記録を一つに見せるために隠れた一致値を自動生成しない。依頼後読戻しは、この一判断・コメント・レビュー状態が一致した場合だけ成功とする。
4. Screen2／Screen4の担当者結果も一行の「担当者の判断」に統一。古い保存値も上記対応で表示する。判断が空なら未記録。未完了照合の既存値を確認済みと見せない条件を維持する。
5. Screen3はレビュー未依頼／空欄時に状態文を出さず依頼ボタンを表示。依頼中・再依頼→レビュー待ち、確認済み→レビュー完了、差し戻し→差し戻し。依頼済みのボタンを隠して状態へ置換。二重の「依頼済みです」説明も除く。進捗一覧は未依頼を表示して履歴を追えるようにする。保存値とフローの通知条件は維持する。

## 実施順序・完成条件

- Studioから6定義を outputs/canvas-20261002-single-judgment-before へ同期し、現在のローカル変更を上書きせず候補を別フォルダーへ作る。
- 最小の確認で、旧一致入力への必須依存が残らないこと、3選択と保存値の対応、読戻し対象と更新対象の一致、転記照合列の保全を確認する。
- 既存の外部送信・保存承認範囲でMicrosoft Power Apps編集サービスへcompile_canvasし、非公開Studio保存後に6定義を読み戻す。
- 既存のテスト件を使い、3画面の戻る位置、担当者入力1つ、問題なし／要対応／判断保留の入力条件、依頼確認→キャンセルと値の保持、一覧とレビューの表示を確認する。AIは下書き保存・依頼確定・照合開始・通知を実行しない。実APIの新しい書込み試験は追加しない。
- 保存後の4画面をcanvas/currentへ反映し、REQUIREMENTS・画面仕様・共通ルール・CHECKS・TASKSへ承認変更と検証限界を記録する。

## 外部操作・復旧

表定義、データ移行、フロー、Excelひな形、クラウド削除、公開、課金は含めない。今回の保存先は既存のPower Apps編集サービスのみ。保存前定義を保持し、不具合時は今回の変更だけ戻す。既存テストデータを消して解決しない。新たな判断一入力での実保存／Teams実通知はユーザー実機確認で行う。構文検査を実保存成功の代わりにしない。
