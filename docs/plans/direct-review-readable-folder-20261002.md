# 役割切替なしのレビューと読みやすい証跡フォルダー名

ユーザーへ具体案を報告し「はい、じゃあそれで対応お願いします」により実行承認済み。独立レビュー・サブエージェント・大規模試験は使わず、変更箇所の最小確認だけ行う。

## 対象と完成条件

1. Screen3の実演役割表示と切替を除く。レビュー待ち（依頼中／再依頼）で元ファイル・照合結果・担当者判断／コメントを見て、そのまま承認／差し戻しを選ぶ。保存ボタンは「レビューを完了」。差し戻し理由必須。承認は確認済みとして保存する。
2. 依頼前は一判断・コメントを入力し、下書き／依頼確認を行える。依頼後は担当者入力を編集不可の表示へ、差し戻し後は再編集・再依頼へ戻す。役割条件だけを状態条件に置き換え、GUID・版・添付2件・処理完了・読戻し・連打抑止は保持する。現在の1アカウントで使う構成の修正であり、本当の別人の認証を追加しない。
3. 新規SharePointフォルダーを「環境A_サーバーA_2026-10-02_20時30分13秒」形式にする。受付createdonのJSTを使用し、表示と同様「架空」を除く。SharePointで使えない記号を安全な文字へ替える。同秒・同名の別件を上書きしないため、重複時だけ短い件IDを末尾に付ける。必要な完全GUIDは内部識別に保持する。
4. フォルダー名だけでは同一件か判定できないので、作成先のGetFolderとファイル存在を確認する。既存URLがある件は保管対象外。衝突した別件のファイルを上書きしない。短い識別文字でも衝突した場合は安全に停止する。
5. 既存フォルダー・URL・過去のTeams通知、完了履歴、照合・Excel出力は変えない。3ファイルの読戻し後のURL保存を維持する。

## 操作契約

| 操作 | 前提 | 書込み／確認 |
| --- | --- | --- |
| 担当者入力・依頼 | 未依頼／差し戻し、処理完了、2添付確認済み | 既存判断・コメント・依頼確認と保存読戻し、役割選択不要 |
| 承認 | 依頼中／再依頼、GUID・版・添付・結果一致、承認選択 | レビュー状態=確認済み、理由空を同一件へ保存・読戻し、同画面に承認結果 |
| 差し戻し | 同上、差し戻し選択・理由あり | 状態=差し戻し、理由を保存・読戻し、同画面に理由 |
| 新規保管 | 既存URLなし、照合完了・元2ファイルと結果Excel確認済み | 読みやすい名前で新規フォルダー作成、衝突確認、3ファイル読戻しとURL保存 |

## 実施・確認

最新6Canvas定義・稼働中の保管フローを別フォルダーに保全。Screen3のみ役割条件と2コントロールを除き、レビュー見出し位置を上へ詰める。共有する一覧・Appは今回変更しない。保管フローの命名・衝突確認だけ変更し、トリガー条件・接続・ファイル内容・通知フローを保ち、同名競合を防ぐため保管フローの並列実行を1件へ制限する。既存ローカル変更を上書きしない。

ローカルの最小契約確認で未依頼／依頼待ち／完了／差し戻しの条件、理由必須・同一件読戻し・フォルダー命名と衝突防止を確認。compile_canvasへ送信して6定義検査後、Studio非公開保存、6定義と保管フローを読戻す。既存件の選択・入力・解除で直接レビュー選択と初回コメント編集を確認し、AIはレビュー確定・新規照合・Teams通知を行わない。新規フォルダーの実生成は利用者の次の照合で確認する。
