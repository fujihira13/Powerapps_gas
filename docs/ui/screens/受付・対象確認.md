## 引き継ぐ役割と固定事項

| 区分 | 内容 | 根拠 |
| --- | --- | --- |
| 受付 | 担当者役が Power Apps で複数の取得済み架空ログを選び、作品が指定場所へ保存する。 | REQUIREMENTS「主要操作」1、U01、T-001 |
| 件別の確認 | ログごとに環境・サーバー・実行回・対象処理日を確認する。対象処理日は操作当日の日付で代用しない。 | REQUIREMENTS「主要操作」1、R01・R13 |
| 開始前 | 処理開始前は選択と入力を修正・取消できる。担当者役が対象を確認して処理を開始する。取消した件は処理せず、証跡 Excel も作らない。 | REQUIREMENTS「主要操作」1～2、U02、C09 |
| 保存失敗 | 保存に失敗したと分かった件には、確定した文言 **「保存できませんでした」** を表示し、その件を Excel へ転記しない。 | REQUIREMENTS「決定」、C08 |
| 開始後 | 進行中の処理を取り消す操作は設けない。件ごとの完了・失敗・結果未確認を追えることは後続の進捗の役割とつなぐ。 | REQUIREMENTS「主要操作」4、U02、C09 |
| 対象外 | 実務ログ・顧客情報・実務の証跡 Excel を使わない。画面に未承認の下書き再開機能や、メール・Teams 通知を加えない。 | REQUIREMENTS「今回は対象外」「仮定」、T-001 |

ここで固定したのは既存の要件・個別回答・完成条件である。表にない表示文言、ボタン名、画面数や見た目を決定したことにはならない。

## 画面の役割整理案（T-005、未承認）

| 項目 | 内容 |
| --- | --- |
| 目的 | 取得済みの架空ログを複数受け付け、件ごとの対象情報と保存結果を確認してから処理を始める。 |
| 主操作 | 複数ログを選ぶ。各件の環境・サーバー・実行回・対象処理日を確認する。作品が指定場所へ保存した結果を踏まえ、対象を確認して処理を開始する。 |
| 補助操作 | 開始前に選択・入力を修正または取消する。保存失敗件の表示を確認する。取消件と保存失敗件は処理対象から外す。 |
| 必要な情報 | 選んだログを件ごとに識別できる情報、環境・サーバー・実行回・対象処理日、件ごとの保存結果。保存失敗が判明した件には正確に「保存できませんでした」と表示する。 |
| この役割には不要な情報 | Excel本文・反映状況の詳細、担当者判断・レビュー結果。これらは後続の役割で扱う。進行中取消操作も置かない。 |
| 入口 | 担当者役が新たな取得済みログの受付を始めるとき。アプリ起動直後の画面と決めたわけではない。 |
| 出口 | 処理開始後に進捗一覧の役割へつなぐ案。開始前の修正・取消中は受付にとどまる。具体的な画面遷移と、全件取消時の表示は未決定。 |

### B案の参考画像から採用する点・しない点

| 区分 | 判断と理由 |
| --- | --- |
| 採用する配置案 | 左に複数件の一覧、右に選択中の1件の詳細を置く。複数件の存在を見ながら、件別の4項目を読みやすく確認できる。 |
| 採用する表示案 | 保存失敗の文言を該当件の近くに置く。C08の「その件に表示」と一致する。 |
| 採用しない仕様化 | 画像のチェックボックスの意味、ファイル名・日付・環境の例、青い配色、ヘッダー名、各ボタンの正確な文言を確定仕様にしない。選択と保存の実現方式、文言、配置の最終判断は未決定。 |
| 採用しない機能 | 画像に描かれていても、要件にない選択方式・保存方式・追加操作を機能として増やさない。開始後の進行中取消も加えない。 |

画像は受付の役割だけを示す参考であり、後続の画面構成や保存成功の判定方法を証明しない。
