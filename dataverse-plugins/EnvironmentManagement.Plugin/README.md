# 環境・サーバー管理の同期保存

`cr6cb_ManageEvidenceDestinations` の主処理として登録する専用プラグイン。既存のRequiredFields.Pluginは登録しない。入力RequestJson、出力ResultJson。削除は提供しない。

環境追加・サーバー追加・両名称変更・両使用終了・両再使用と一覧読取を扱う。サーバーを親とし、その下に複数の環境を登録する。更新前の全対象ID／版、重複、名前長、親サーバーの使用状態、追加時の保存先利用確認と版を検証する。サーバー全体の使用状態変更で個別環境の使用状態を書き換えない。旧画面からの更新は拒否する。

変更操作は同期トランザクション外なら拒否。共通の既存設定行を値を変えず楽観的同時実行チェック付きで更新し、ロック取得後に全件を読み直して再検証する。その共通行の版／更新日時は変わる。対象変更も版を照合して保存する。書込み後の失敗は例外を伝播し、Dataverseに全変更の取消を任せる。読取操作はロック・書込みなし。

管理フローのPower Apps同期応答はトリガーの同時実行数制限と併用しない。保存処理の共通ロックが競合を扱う。新しい表・権限は追加しない。

ビルドは`scripts/build_environment_management.ps1`。既存のGit対象外の秘密の署名鍵を再利用する。登録は`scripts/deploy_environment_management.py --approved`。コード更新で公開鍵を変えない。

保存契約16検査とビルドは合格。実UIでは架空2行の親子管理操作・重複／古い版／旧画面の拒否を確認。故意のクラウド途中障害は注入せず、例外伝播はローカル代替サービスで確認。最新結果はdocs/plans/server-first-management-20261003.md。
