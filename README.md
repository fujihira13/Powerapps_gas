# 架空ログ証跡アプリ

Power AppsとPower Automateで架空のサーバーログを受け付け、バッチ入力Excelに予定されたMQ IDとログに記録されたMQ IDを照合するポートフォリオ作品です。ログ末尾の`ALL SUCCESS`は処理が最後まで走った表示として扱い、IDの記録漏れがない証拠とは扱いません。

**現在の状態：Developer環境の非公開アプリです。** 作者アカウントでStudioのプレビューを操作できます。一般公開・別アカウントへの共有・実務データでの確認はしていません。

## まず完成済みの結果を見る

1. [架空ログ証跡アプリの編集画面](https://make.powerapps.com/e/c1719a14-6cac-eb5b-b598-2254af1c64b7/canvas/?action=edit&app-id=%2Fproviders%2FMicrosoft.PowerApps%2Fapps%2F3186a908-ac5b-48cc-90f5-d50e07282ee7)を作者アカウントで開き、右上の**▶**でプレビューします。「公開」は押しません。
2. プレビューが受付画面なら右上の「進捗一覧」を押します。ログ名`mq-id-5-items-20260928.txt`、受付日時**2026-09-28 07:02:56 JST**、件ID末尾`ed89fb2c…`の行を探します。
3. その行の「ログと結果を見る」を押します。予定5件、ログ記録4件、差異1件が示され、差異一覧には`MQ-0003 — ログに記録されていないID`だけが表示されます。
4. 「結果Excelを開く」を押します。`証跡`シートには件ID・受付日時・元ログ全文、`MQ_Comparison`シートには5つの予定IDと各判定が入っています。`MQ-0003`だけ「ログ未記録・要確認」です。[確認済みの結果Excelを直接開く](https://fujimasa13-my.sharepoint.com/personal/fujimasa_fujimasa13_onmicrosoft_com/_layouts/15/Doc.aspx?sourcedoc=%7B3C2C60E4-AC7D-45C9-A5E8-B26BFA0F7214%7D&file=ed89fb2c-bfba-f111-b377-7ced8d3141aa.xlsx&action=default&mobileredirect=true&web=1)こともできます（同じアカウントのアクセス権が必要です）。

この件は**処理済み**です。画面の確認だけなら新しい照合を始める必要はありません。過去の件ID末尾`d21172cc…`は当時の日時比較の不具合で「結果不明」のまま保全しており、再実行しません。

## 新しい架空件を操作する場合

この操作はDataverseに新しい件と添付を作り、結果Excelを1冊作ります。既存の結果を見るだけなら上の手順で足ります。

1. プレビューの「進捗一覧」で「新しい照合を開始」を押します。受付画面が最初から表示されている場合はそのまま進みます。
2. 「更新対象一覧（Excel）」に`.xlsx`を1冊、「サーバーログ（txt）」に`.txt`を1件、それぞれの「ファイルを添付」から選びます。片方だけでは開始できません。
3. 環境とサーバーを確認します。対象処理日は開いた日の値が初期表示され、必要なら変更できます。**ログ本文の日付・環境・サーバーと画面の値を一致させてください。実行回の入力はありません。**
4. 「照合を開始」を**1回だけ**押します。アプリが内部で件と2ファイルを保存・確認してから処理を始め、進捗一覧へ移動します。同名の過去件が見つかった場合は警告を読み、新しい件としてよい場合だけ続行します。同名警告はファイルの**名前**によるもので、内容が同じことは証明しません。
5. 進捗一覧で処理の完了を確認し、「ログと結果を見る」から差異と結果Excelを開きます。「要確認」は人による確認が必要という意味です。結果不明・停止の件を成功扱いせず、同じ件を再開始しません。

再現用の架空ファイルは[サーバーログ](samples/mq-id/mq-id-5-items-20260928.txt)と[更新対象一覧](samples/mq-id/mq-id-5-items-20260928.xlsx)です。ログ本文の処理日は**2026-09-28**なので、この見本を使う場合は画面の対象処理日もその日に変更します。環境は画面上の「環境A」（保存値は`架空環境A`）、サーバーは「サーバーA」（保存値は`架空サーバーA`）です。入力Excelの`Batch_Input`シートはA2に`MQ_ID`、A3以降に`MQ-0001`～`MQ-0005`を持ちます。ログは4 IDだけを記録するため、想定結果は欠落`MQ-0003`と「要確認」です。同じ日・環境・サーバー・ファイル名でも、新しい受付なら別の件IDで保存できます。

## 画面と確認範囲

アプリは「受付・対象確認」「進捗一覧」「ログと結果の確認」「レビュー」の4画面です。新規受付では「照合を開始」の1操作で内部保存と処理を順に行います。結果Excelを確認した後に担当者の照合・判断とレビュー依頼を記録できます。同一アカウントでの役割切替は独立した権限管理の証明ではありません。

新しい2ファイル受付・1操作開始・MQ欠落検知は、上記の架空1件で限定的に実機確認しました。入力不足、同名警告、通信失敗、差異0件、終了行なし、旧件の閲覧専用、今回の新規件でのレビュー操作、並行開始時のサーバー側ロックは実機未確認です。一般公開の受入も未実施です。詳細な実測値と未確認事項は[作業と引き継ぎ](docs/TASKS.md)、合格条件は[確認方法](docs/CHECKS.md)、仕様は[要件](docs/REQUIREMENTS.md)を参照してください。
