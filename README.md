# 架空ログ証跡アプリ

Power AppsとPower Automateで、架空の運用ログを受付し、処理状況とExcel証跡を件ごとに追跡するポートフォリオ作品です。正常な複数件の転記とExcel実内容、担当者確認からレビュー差し戻し・再依頼・確認済みまでをDeveloper環境で確認しています。

## 開く場所

このアプリは**未公開**です。作者アカウントのPower Apps Studioでプレビューできます。

[Power Apps Studioで編集・プレビューを開く](https://make.powerapps.com/e/c1719a14-6cac-eb5b-b598-2254af1c64b7/canvas/?action=edit&app-id=%2Fproviders%2FMicrosoft.PowerApps%2Fapps%2F3186a908-ac5b-48cc-90f5-d50e07282ee7)

リンクを開いたら右上の▶を押してプレビューします。起動後は進捗一覧が表示されます。アプリの公開や共有は行っていません。

## 画面の使い方

1. **進捗一覧**：既存の架空案件と、ログ保存・転記・Excel反映・照合・判断・レビューの状態を確認します。「件を確認」で詳細へ進みます。「新しい件を受付」で新規登録を始めます。
2. **受付・対象確認**：ログを選び、環境・サーバー・実行回・対象処理日を入力して「保存」します。保存と「処理開始」は別操作です。保存だけではExcelを作りません。
3. **件ごとの確認**：保存済みログとExcelの実内容を照合し、転記照合と処理結果の判断・コメントを別々に記録します。実演用の役割表示は別人の権限を意味しません。
4. **レビュー**：担当者の照合と判断記録の後にレビューを依頼します。レビュアー役で「確認済み」または理由付き「差し戻し」を記録します。差し戻し時は担当者記録を直して再依頼できます。

## MQ ID照合

### 確認済みの現況

Developer環境の非公開アプリでは、Canvas定義をStudioに保存し、MQ結果用7列、Office Script 3件（書込み／読戻し用はv3.0）、Flow guard更新の読戻しを確認しました。2026-09-27の架空run92704を1回処理し、Dataverseで状態「転記済み」、Excel照合「全文一致」、MQ状態「要確認」、終端表示あり、失敗理由なしを確認しました。

出力ブックの`証跡`と`MQ_Comparison`の2シートも読戻し済みです。予定5件・ログ記録4件・欠落1件（`MQ-0003`）で、他の4件は「記録あり」、`MQ-0003`は「ログ未記録・要確認」と表示されています。`ALL SUCCESS`はログ終端の表示であり、全IDが記録されたことを意味しません。この見本で欠落IDを「要確認」として扱うことが確認できました。アプリはDeveloper環境内の非公開状態で、公開・共有していません。

進捗一覧と件ごとの確認画面にも、5／4／1と欠落ID`MQ-0003`が表示されることを確認しました。この1件は既に処理済みです。run92701～92704を再開始しないでください。ログだけの従来経路、レビュー経路、元入力ブック無変更など、残る完成条件は[docs/TASKS.md](docs/TASKS.md)のT-013に記録しています。全機能の受入完了とは扱いません。

### 5件の架空サンプルの確認

- [5件のバッチ入力](samples/mq-id/mq-id-5-items-20260927.xlsx): `Batch_Input`シートのA2が`MQ_ID`、A3以降に5件。
- [run92704用の実行ログ](samples/mq-id/mq-id-5-items-20260927-run92704.txt): 4件のID記録と末尾の`ALL SUCCESS`を含み、`MQ-0003`は記録しません。

この架空サンプルは処理済みです。ポートフォリオでは再保存・再開始せず、進捗一覧から環境A／サーバーA／run92704／2026-09-27の件を開いてください。処理「転記済み」、Excel「全文一致」、MQ「要確認」、予定5・記録4・欠落1と`MQ-0003`を確認し、証跡Excelで`証跡`・`MQ_Comparison`の両シートを参照します。

MQ対象を新たに受け付ける場合は、`.txt`と`.xlsx`を同じ件へ添付し、両方を選んでから「ログを選ぶ」を押します。保存後の「処理開始」は別操作です。ログだけを選んで確定した後にブックを追加する経路は、添付コントロールの`Items`がサポート対象外の参照方法を含むため案内していません。

欠落があるこの例ではMQ状態「要確認」が正しい結果です。`ALL SUCCESS`だけで全ID成功とは判断しません。すでに処理したrun92704を再実行しないでください。実行後の詳細な履歴はT-013を参照してください。

## 停止ケースと制限

`normal-demo-run101.txt`は本文の日付が2026-09-25、画面指定が2026-09-26で不一致のため停止した確認用履歴です。これは正常動作のデモではありません。元件を再実行しないでください。進捗に「停止」または「要確認」が出た件も成功扱いせず、そのまま保全します。

2026-09-26に停止件の誤表示を直し、非公開アプリへ反映しました。プレビューの進捗一覧ではrun101は「停止／Excel実反映：未確認／転記照合：—／処理結果の判断：—」と表示され、件詳細のExcelリンク、照合・判断欄、「確認を記録」、「レビューを依頼」は無効でした。正常D/Gの「処理完了／反映確認済み」と、Dの「一致／正常」は維持されています。run101は再実行せず、保存データやExcelも変更していません。詳細は[docs/CHECKS.md](docs/CHECKS.md)と[docs/TASKS.md](docs/TASKS.md)を参照してください。

このポートフォリオ版では、確定した保存失敗後の同一件再保存、Excel失敗後の再実行、保存後取消からの再開は提供しません。別人アカウントの権限確認、一般公開、実務データ利用も対象外です。Developer環境での個人プレビューに必要な利用権・将来の費用条件は未確定です。
