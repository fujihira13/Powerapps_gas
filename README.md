# 架空ログ証跡アプリ

Power AppsとPower Automateで架空のサーバーログを受け付け、バッチ入力Excelに予定されたMQ IDとログに記録されたMQ IDを照合するポートフォリオ作品です。ログ末尾の`ALL SUCCESS`は処理が最後まで走った表示として扱い、IDの記録漏れがない証拠とは扱いません。

**現在の状態：Developer環境の非公開アプリです。** 作者アカウントでStudioのプレビューを操作できます。一般公開・別アカウントへの共有・実務データでの確認はしていません。

## まず完成済みの結果を見る

1. [架空ログ証跡アプリの編集画面](https://make.powerapps.com/e/c1719a14-6cac-eb5b-b598-2254af1c64b7/canvas/?action=edit&app-id=%2Fproviders%2FMicrosoft.PowerApps%2Fapps%2F3186a908-ac5b-48cc-90f5-d50e07282ee7)を作者アカウントで開き、右上の**▶**でプレビューします。「公開」は押しません。
2. 「進捗一覧」で、ログ名`mq-id-5-items-runless.txt`、受付日時**2026-09-27 15:17:22 JST**、件ID末尾`13b55219…`の件を探します。同名の件が2つあるので日時と件IDで区別します。
3. その件の「件を確認」を押します。処理は「転記済み」、Excelは「全文一致」、MQ照合は「要確認」、予定／記録／欠落は**5／4／1**、欠落IDは`MQ-0003`です。
4. 件ごとの確認画面の「結果Excel」を開きます。`証跡`シートには件ID・受付日時・元ログ全文、`MQ_Comparison`シートには5つの予定IDと各判定が入っています。`MQ-0003`だけ「ログ未記録・要確認」です。[確認済みの結果Excelを直接開く](https://fujimasa13-my.sharepoint.com/personal/fujimasa_fujimasa13_onmicrosoft_com/_layouts/15/Doc.aspx?sourcedoc=%7B8BE0BB7D-D4C0-472C-8407-AB0187B83ED2%7D&file=13b55219-3bba-f111-b377-7ced8d3141aa.xlsx&action=default&mobileredirect=true&web=1)こともできます（同じアカウントのアクセス権が必要です）。

この件は**処理済み**です。もう一度「処理開始」は押さないでください。もう1つの同名件（受付日時15:15:13、件ID末尾`d21172cc…`）は結果Excel自体を確認できたものの、当時の日時比較の不具合で件状態が「結果不明」のままです。修正後も既存件を再実行せず保全しています。成功例として提示するのは15:17:22の件です。

## 新しい架空件を操作する場合

この操作はDataverseに新しい件と添付を作り、「処理開始」で結果Excelを作ります。既存の結果を見るだけなら上の手順で足ります。

1. プレビューの「進捗一覧」右上で「新しい件を受付」を押します。
2. **1件だけ**受け付けます。「ログ」欄に`.txt`を添付します。MQ照合なら同じ添付欄にバッチ入力`.xlsx`も1冊追加し、「MQ照合」を選びます。ログのみの場合は`.txt`だけにして「ログのみ」を選びます。旧画面の「ログを選ぶ」ボタンはありません。
3. 環境とサーバーを確認します。対象処理日は開いた日の値が初期表示され、必要なら変更できます。**ログ本文の日付・環境・サーバーと画面の値を一致させてください。実行回の入力はありません。**
4. 「保存」を押し、保存済みの表示を確認します。この時点ではExcel転記は始まりません。同名の過去件が見つかった場合は、画面の警告で過去件を確認し、新しい件としてよい場合だけ続行します。同名警告はファイルの**名前**によるもので、内容が同じことは証明しません。
5. 保存済みの件で「処理開始」を1回押します。進捗一覧で件の状態を確認し、完了後に「件を確認」から結果Excelを開きます。結果不明・停止・要確認が出た件を成功扱いせず、同じ件を再開始しません。

再現用の架空ファイルは[実行回のないログ](samples/mq-id/mq-id-5-items-runless.txt)と[5件のバッチ入力Excel](samples/mq-id/mq-id-5-items-20260927.xlsx)です。ログ本文の処理日は**2026-09-27**なので、この見本を使う場合は画面の対象処理日もその日に変更します。環境は「架空環境A」、サーバーは「架空サーバーA」です。入力Excelの`Batch_Input`シートはA2に`MQ_ID`、A3以降に`MQ-0001`～`MQ-0005`を持ちます。ログは4 IDだけを記録するため、想定結果は欠落`MQ-0003`と「要確認」です。同じ日・環境・サーバー・ファイル名でも、新しい受付なら別の件IDで保存できます。

## 画面と確認範囲

アプリは「受付・対象確認」「進捗一覧」「件ごとの確認」「レビュー」の4画面です。保存と処理開始は別操作で、結果Excelを確認した後に担当者の照合・判断とレビュー依頼を記録できます。同一アカウントでの役割切替は独立した権限管理の証明ではありません。

1件受付・同日再受付・実行回なし・MQ欠落検知は、上記の架空2件で限定的に実機確認しました。ログのみの新仕様での実機処理、今回の新規件を選んだレビュー操作、並行開始時のサーバー側ロックは未確認です。一般公開の受入も未実施です。詳細な実測値と未確認事項は[作業と引き継ぎ](docs/TASKS.md)、合格条件は[確認方法](docs/CHECKS.md)、仕様は[要件](docs/REQUIREMENTS.md)を参照してください。
