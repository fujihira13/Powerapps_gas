# 架空ログ証跡アプリ

Power AppsとPower Automateで、架空の運用ログを受付し、処理状況とExcel証跡を件ごとに追跡するポートフォリオ作品です。正常な複数件の転記とExcel実内容、担当者確認からレビュー差し戻し・再依頼・確認済みまでをDeveloper環境で確認しています。

## 開く場所

このアプリは**未公開**です。作者アカウントのPower Apps Studioでプレビューできます。

[Power Apps Studioで編集・プレビューを開く](https://make.powerapps.com/e/c1719a14-6cac-eb5b-b598-2254af1c64b7/canvas/?action=edit&app-id=%2Fproviders%2FMicrosoft.PowerApps%2Fapps%2F3186a908-ac5b-48cc-90f5-d50e07282ee7)

リンクを開いたら右上の▶を押してプレビューします。起動後は進捗一覧が表示されます。アプリの公開や共有は行っていません。

## 画面の使い方

1. **進捗一覧**：既存の架空案件と、ログ保存・転記・Excel反映・照合・判断・レビューの状態を確認します。「件を確認」で詳細へ進みます。「新しい件を受付」で新規登録を始めます。
2. **受付・対象確認**：ログを選び、環境・サーバー・実行回・対象処理日を入力して「保存」します。保存と「処理開始」は別操作です。保存だけではExcelを作りません。
3. **件ごとの確認**：保存済みログとExcelの実内容を照合し、転記照合と処理結果の判断・コメントを別々に記録します。実演用の役割表示は別人の権限を意味しません。
4. **レビュー**：担当者の照合と判断記録の後にレビューを依頼します。レビュアー役で「確認済み」または理由付き「差し戻し」を記録します。差し戻し時は担当者記録を直して再依頼できます。

## 正常な結果を見る

既存の正常実演は、進捗一覧で次の2件を確認してください。

- 環境D／サーバーD／実行回2／2026-09-25
- 環境G／サーバーG／実行回2／2026-09-25

画面では、対象の行を見つけて「件を確認」を押し、詳細画面の「証跡Excel」を開いてください。各ブックのEvidence表は9列・データ1行で、4項目とログ全文が元データに一致します。2件とも1回の処理開始で別々のExcelが1冊ずつ作成されました。再実演すると重複登録になるため、既存件をもう一度開始しないでください。

レビュー済みの例は、進捗一覧で**環境B／サーバーB／実行回2／2026-09-25**の件（元ログ`normal-c-readback.txt`）を探してください。レビュー状態「確認済み」を確認します。レビュー詳細を表示する場合は、その行の「レビューを確認」から開きます。これは同じアカウント内で担当者役とレビュアー役を切り替えた実演で、別人の権限確認ではありません。

正常転記・レビュー記録の実施証拠は[docs/TASKS.md](docs/TASKS.md)のT-011を参照してください。

1. [Power Apps Studio](https://make.powerapps.com/e/c1719a14-6cac-eb5b-b598-2254af1c64b7/canvas/?action=edit&app-id=%2Fproviders%2FMicrosoft.PowerApps%2Fapps%2F3186a908-ac5b-48cc-90f5-d50e07282ee7)を開き、右上の▶でプレビューします。
2. 「新しい件を受付」→「ファイルを添付」で上記ログを選び、「ログを選ぶ」を押します。受付画面にファイル名が表示されたことを確認します。
3. 環境「架空環境A」、サーバー「架空サーバーA」、実行回「8372」、対象処理日「2026-09-26」を入力し、「保存」を1回押します。画面に「保存済み」と表示された後も受付画面に留まります。
4. 受付画面の右下にある「処理開始」を1回だけ押します。開始が受け付けられると進捗一覧へ移動します。まだ「処理中」なら少し待ち、「新しい件を受付」→「進捗一覧」で一覧を開き直して状態を更新します。「処理完了」および「反映確認済み」を確認します。停止・要確認・結果不明になった場合は再度開始せず、その時点で中止します。
5. 「件を確認」→「証跡Excel」を開きます。Evidence表が9列・データ1行で、ログ名、4項目、対象日、ログ全文が元ログと一致することを確認します。
6. 件ごとの確認画面でExcel実内容を照合し、転記内容の照合を「一致」、処理結果の判断を「正常」として選び、「確認を記録」を押します。コメントは任意です。「確認を記録」の後に「レビューを依頼」が使えるようになるので、続けて押します。
7. 進捗一覧へ戻り、その件の「レビューを確認」からレビュー画面を開きます。「レビュアー役に切り替える」を押し、「レビュー結果」で「確認済み」を選び、「レビュー結果を記録」を押します。進捗一覧に戻り、状態「確認済み」を確認します。

処理開始を伴う実演では8372を含む既存の実行回を使い回さず、ログ本文の日付・識別情報と画面入力を一致させてください。8372でこの一回限りの実演を行った後は、別の未使用実行回を使います。

## 停止ケースと制限

`normal-demo-run101.txt`は本文の日付が2026-09-25、画面指定が2026-09-26で不一致のため停止した確認用履歴です。これは正常動作のデモではありません。元件を再実行しないでください。進捗に「停止」または「要確認」が出た件も成功扱いせず、そのまま保全します。

現行の非公開アプリでは、この停止件に過去の「一致／正常」が残って表示される不具合があります。画面上の「Excel実反映：未確認」が実際の状態であり、転記成功の証拠にはなりません。表示修正候補はGitに保存済みですが、MCP検査とStudio保存は未実施です。

このポートフォリオ版では、確定した保存失敗後の同一件再保存、Excel失敗後の再実行、保存後取消からの再開は提供しません。別人アカウントの権限確認、一般公開、実務データ利用も対象外です。Developer環境での個人プレビューに必要な利用権・将来の費用条件は未確定です。
