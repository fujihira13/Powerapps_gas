# T-007 Dataverse CLI 接続診断記録

日付: 2026-09-25 (JST)
対象: 承認済みDeveloper環境 `https://org3d6ad684.crm7.dynamics.com/`
対象表: `cr6cb_evidencecase`
担当範囲: ローカル診断と、同じメタデータGETの短時間再試行1回。行データの読取・作成・更新はこの担当の範囲外。

## 実施内容

秘密値・アカウント識別子・プロキシ値を表示せず、ローカルCLI起動、認証キャッシュの存在、プロキシ設定の有無、DNS/TCP/HTTP到達性を確認した。通常サンドボックスと、短い診断コマンドについて自動審査を通過した昇格実行を区別した。

### 通常サンドボックス内

- DNS: 対象ホストの名前解決に成功。2アドレスを返した。
- TCP 443: `SocketException` 10013（Access denied）で失敗。
- 認証なしHTTPS HEAD: TCP接続段階で失敗し、HTTP状態は得られなかった。
- Power Platform CLI `pac --version`: 5秒で応答せず、当該診断プロセスを終了した。
- Node.js `--version`: 終了コード0、61 ms。
- ローカルの `@microsoft/dataverse` CLI（1.0.80）の `api request --help`: 終了コード0、約0.4秒。CLI自体のローカル起動はできた。
- proxy環境変数は未設定。ユーザーのWindowsプロキシは無効、WinHTTPはdirectと表示された。プロキシの値は取得・表示していない。

### 昇格実行による短時間診断

- DNS: 成功、2アドレス。
- TCP 443: 接続成功、約20 ms。
- 認証なしHTTPS HEAD: HTTP 302、約119 ms（リダイレクトは追跡していない）。
- `pac auth list`: 終了コード0、約2.9秒。出力本文は表示・保存せず、対象URLを含む既存プロファイルがあることだけ確認した。ローカルのPowerApps CLIキャッシュディレクトリと認証プロファイル／MSALトークンキャッシュのファイル種別の存在も確認したが、ファイル内容は読んでいない。
- `pac --version` は昇格実行でも8秒で応答せず、診断プロセスを終了した。この挙動の原因は未確認。
- 許可済みの対象に対して同じ読み取り専用メタデータGETを一度だけ実行した。Dataverse CLIは終了コード0、HTTP 200を4.37秒で返し、`EntitySetName` は `cr6cb_evidencecases` だった。応答本文・認証値はファイルに保存していない。標準出力・標準エラーに認証プロンプト文言はなかった。画面操作はしていないため、別ウィンドウの有無は未確認。

## 判定

通常サンドボックスではTCP接続が明示的に拒否され、昇格実行では同じ宛先のTCP接続、HTTPS応答、認証付きメタデータGETが成功した。この差は、前回の30秒超タイムアウトをサンドボックスの外向きネットワーク制限が起こした有力な説明である。

ただし、前回記録のGETはHTTP状態を受け取れず、サーバーへの送達有無は遡って確定できない。今回のHTTP 200は今回の再試行の結果だけを示す。今回のGETは認証付きで成功した。どの認証キャッシュ項目が使われたかは個別に追跡していない。`pac --version` の停止は別の未解決事項だが、`@microsoft/dataverse` CLIのGET成功を妨げなかった。

- この診断ではDataverse行のGET、POST、PATCH、その他の更新要求を行っていない。
- 既存記録の30秒超メタデータGETは送達不明。今回の再試行は読取GETとしてHTTP 200を確認済み。
- POST/PATCH、最大8件の作成試験、作成行の読戻し、条件付き更新は未実施。
