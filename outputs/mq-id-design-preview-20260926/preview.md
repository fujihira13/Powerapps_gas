# MQ更新の照合見本（未連携）

このフォルダーは、実際の作業順を架空データ5件で表した設計見本。Power Apps、Power Automate、クラウドのExcelにはまだ連携していない。この見本を実行済みのアプリ機能として扱わない。

`batch-input.xlsx`がバッチ入力用Excel、`mock-log.txt`が実行後ログ、`mq-id-preview.xlsx`が抽出・照合結果の見本。Excel内の短い見出しは英語にし、ここで日本語の意味を説明する。

## 作業の順番

1. バッチ入力用Excelの冒頭にはタイトルやヘッダーがあり、その下の同じ列に更新予定のMQ IDが並ぶ。この見本では5件。
2. バッチがサーバーを更新し、成功したMQ IDだけを実行ログに記録する。この見本のログには4件を記載する。
3. ログ末尾の`ALL SUCCESS`は**バッチが最後まで動いてログを書き終えた印**。すべてのMQ IDが反映された意味ではない。
4. 入力用Excelの5件とログの4件を突き合わせ、ログにない`MQ-0003`を確認対象として示す。

| 項目 | 見本の結果 |
| --- | --- |
| バッチの終了 | `ALL SUCCESS`を確認 |
| 入力用Excelの予定ID | 5件 |
| ログに記録されたID | 4件 |
| ログにないID | `MQ-0003`（1件） |

`ALL SUCCESS`がないログは、最後まで出力されたと確認できないため、欠けたIDを個別の更新失敗と確定しない。今回の見本では`MQ_BOX_ID=MQ-0001`のように行頭から始まる行だけをID記録とみなし、文中のIDや`MQ_BOX_STATUS=READY`を数えない。

この比較の目的は、元のバッチ用Excelや既存の関数入りExcelを変更せず、見落としやすい未記録IDを担当者に示すこと。実務で使うログの正確な書式、入力Excelの列、画面表示と完成条件は見本確認後に正式資料で決める。約100件への拡張、アプリ実装、クラウド試験はまだ行っていない。
